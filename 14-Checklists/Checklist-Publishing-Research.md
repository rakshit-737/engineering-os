# Checklist: Publishing Research

Covers writing, artifacts, and submission. For experiment-level reproducibility, use the research toolkit's Reproducibility-Checklist alongside this one.

## Claims and evidence

- [ ] Write each contribution as one sentence and map it to the table or figure that supports it.
- [ ] Confirm every number in the paper is regenerated by a script in the repository.
- [ ] Report variance (standard deviation or confidence intervals) over multiple seeds for key results.
- [ ] Compare against strong, properly tuned baselines, and state the tuning budget for each.
- [ ] Include ablations for each component you claim matters.
- [ ] State limitations and failure cases explicitly in their own section.

## Writing

- [ ] Check the venue's page limit, template, and anonymity rules before final formatting.
- [ ] Make the abstract state problem, method, main result, and why it matters.
- [ ] Define every symbol and acronym on first use.
- [ ] Check all figures are readable in grayscale and at print size.
- [ ] Verify every citation resolves and cite the original source, not a secondary one.
- [ ] Have someone outside the project read it and mark the first place they got lost.

## Artifacts

- [ ] Release code with a README that reproduces the main table with one command.
- [ ] Pin dependencies and record hardware used for the reported runs.
- [ ] Release model checkpoints or trained weights if licensing permits.
- [ ] Publish datasets or scripts to obtain them, with a datasheet describing collection and license.
- [ ] Anonymize repository links for double-blind review (e.g. an anonymous mirror).
- [ ] Choose a license for code and data.

## Ethics and compliance

- [ ] Confirm dataset licenses permit your use and redistribution.
- [ ] Remove personal data from released data or document consent and approval.
- [ ] Complete the venue's ethics or broader-impact statement honestly.

## Submit and after

- [ ] Submit a day early; upload systems slow down near deadlines.
- [ ] Post a preprint if the venue allows it.
- [ ] Tag the exact code version used for the camera-ready.
- [ ] Archive code and data with a DOI (e.g. Zenodo) for long-term access.
