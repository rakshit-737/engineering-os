# Reproducibility Checklist

Goal: a stranger with your repo and paper regenerates your headline numbers within seed noise. Many venues ask for a reproducibility checklist; this one covers the common items. Always also fill the venue's own checklist.

## Code

- [ ] Repo contains all training, evaluation and preprocessing code used for reported results
- [ ] README has install steps and one command per table or figure
- [ ] Dependencies pinned (lockfile or `requirements.txt` with versions)
- [ ] Python, framework, CUDA and OS versions stated
- [ ] Commit or tag for the submitted version recorded
- [ ] License file present

## Data

- [ ] Dataset names, versions and sources cited
- [ ] Download or access instructions scripted or documented
- [ ] Split files (IDs) included or deterministically generated
- [ ] Preprocessing is a script, not manual steps
- [ ] Checksums of processed data recorded
- [ ] Licence allows the way you use and share the data

## Experiments

- [ ] All hyperparameters for every reported run are in config files
- [ ] Hyperparameter search space, trial count and selection criterion reported
- [ ] Number of seeds stated; mean ± std (or confidence intervals) reported
- [ ] Test set used only for final evaluation
- [ ] Compute reported: hardware type, number of devices, approximate training time
- [ ] Every number in the paper maps to a run ID in [[Experiment-Tracker]]

## Verification

- [ ] Fresh clone into a clean environment (new venv or container) reproduces at least one headline number
- [ ] Someone else followed the README without your help
- [ ] Pretrained checkpoints (if released) load and give the reported metric
- [ ] Known sources of non-determinism documented

## Paper

- [ ] Method section detailed enough to re-implement without the code
- [ ] Baseline setups described (re-run vs quoted)
- [ ] Limitations section states what the results do not show
