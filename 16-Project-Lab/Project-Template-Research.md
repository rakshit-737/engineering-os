# Project Template: Research

For projects whose output is knowledge (a paper, report, or benchmark) rather than a product. Finish with [[Checklist-Publishing-Research]].

Start from [[Project-Template]] and add the sections below. Target levels refer to [[Project-Maturity-Model]].

## Domain-specific sections

- **Research question:** one falsifiable question and hypothesis
- **Related work:** the closest 5 to 10 papers and the gap
- **Experimental design:** datasets, baselines, metrics, seeds, compute budget
- **Results log:** dated entries of every run, including failures

## Extra requirements

- [ ] Every reported number regenerated by a script.
- [ ] Multiple seeds with variance reported.
- [ ] Baselines tuned with a stated budget.
- [ ] Negative results recorded, not deleted.
- [ ] Code and data release plan decided before writing.

## Project ideas

### 1. Retrieval strategy benchmark for technical notes

- **Target level:** Level 5
- **Scope:** Compare BM25, dense, and hybrid retrieval on a labeled question set over technical Markdown.
- **Stack:** Python, rank_bm25, sentence-transformers, pandas
- **Milestones:**
  1. Build labeled question set
  2. Implement three retrievers
  3. Evaluate recall@k and MRR with seeds
  4. Write report with error analysis
- **What makes it stand out:** Clean benchmark with released data and reproducible numbers.

### 2. LLM judge reliability study

- **Target level:** Level 5
- **Scope:** Measure agreement between LLM judges and human labels across rubric designs.
- **Stack:** Python, several model APIs, human-labeled sample
- **Milestones:**
  1. Collect and label outputs
  2. Design rubric variants
  3. Measure agreement and bias (position, length)
  4. Paper-style write-up
- **What makes it stand out:** Directly useful to practitioners using [[Pattern-LLM-as-Judge]].

### 3. Static analysis false-positive study

- **Target level:** Level 4
- **Scope:** Quantify and categorize false positives of an open-source SAST tool on real projects.
- **Stack:** Semgrep or CodeQL, a set of open-source repos, labeling sheet
- **Milestones:**
  1. Select repos and run tool
  2. Label a sample of findings
  3. Categorize root causes
  4. Propose and test rule fixes
- **What makes it stand out:** Empirical results plus contributed rule improvements.
